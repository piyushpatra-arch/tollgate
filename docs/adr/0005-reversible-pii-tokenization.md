# ADR-0005: Reversible, request-scoped PII tokenization

**Status:** Accepted
**Date:** 2026-09-24
**Deciders:** Piyush (architect)

## Context

KYC and loan workflows are full of personal data. Models, and especially future hosted
models, should not receive SSNs, account numbers, or names. But a KYC agent must still
compare values across documents ("is the pay-stub name the same as the application name?").

## Decision

Detect PII with **Microsoft Presidio** (spaCy NER plus pattern recognizers) and replace each
value with a **placeholder token** such as `<PERSON_1>` or `<US_SSN_1>`. Tokens are
**consistent within a request**: the same value always maps to the same token, so equality
comparisons still work. A system notice tells the model to treat tokens as opaque. Tokens are
restored in the response returned to the caller. For JSON outputs, restoration happens inside
the parsed structure, so values containing quotes or newlines cannot corrupt the JSON.

The token map lives only in memory for the duration of the request. It is never logged or
persisted.

## Options Considered

| Option | Pros | Cons |
|---|---|---|
| A. Irreversible masking (`***`) | Simplest | Destroys cross-document comparison; useless answers |
| B. Request-scoped reversible tokens (chosen) | Preserves equality semantics; caller gets usable output | Detection is imperfect; tokens can confuse small models |
| C. Format-preserving encryption / vault service | Stable across requests | Heavier infrastructure; key management; out of scope for v1 |

## Consequences

- Easier: sending regulated documents to any model tier; audit shows entity *counts* only.
- Harder: NER is imperfect. v1 uses `en_core_web_sm` for footprint. Span clean-up rules trim
  role words ("Applicant …") and stop names at line breaks. A larger spaCy model is a config
  swap.
- Near-duplicates (e.g. "Dana Whitfield" vs "D. Whitfield") get different tokens, which is
  the correct behavior for a mismatch check.
